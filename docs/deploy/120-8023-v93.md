## 认证（含 8023 上线时的 Origin 修复）

首次登录报 **「请求来源不被允许，请从系统入口重新打开登录页」**。根因不是 nginx，而是
`server/auth-session.mjs` 里的 `checkOrigin(req, APP_ORIGINS)`：只接受精确 Origin 白名单，
`APP_ORIGINS` 当时只有 `https://120.26.198.46:8020`。

修复（已在线上执行）：

| 项 | 值 |
|---|---|
| 配置位置 | `/etc/systemd/system/kepu-auth.service` 的 `Environment=APP_ORIGINS=` |
| 改前 | `https://120.26.198.46:8020` |
| 改后 | `https://120.26.198.46:8020,https://120.26.198.46:8023`（逗号分隔，无通配符） |
| 备份 | `/etc/systemd/system/kepu-auth.service.bak-20261127-162053` |
| 生效 | `systemctl daemon-reload && systemctl restart kepu-auth` |

验证方式（不需要真实口令）：用错误口令打 `/api/auth/login`，带 `Origin: ...:8023`。
- 修复前：403「请求来源不被允许」；
- 修复后：**401「用户名或密码错误」** —— 说明来源已放行，只是口令不对。

真实账号登录（`yanshi`）实测：`/login.html` → 提交 → `/index.html`，无报错；
再进 `/sandbox.html`：`__stage` 存在、`THREE.REVISION=180`、`renderer.info.render.calls=293`、pageerror 0。

Cookie 按 host 作用域、不区分端口，所以 8020 的登录态在 8023 直接可用。
