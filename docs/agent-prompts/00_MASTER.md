# 项目总控规则（项目落库版 V1.0）

日期：2026-11-22
适用项目：科普智能体综合服务平台 / 石油产业链数字沙盘 V3.5.1
来源：用户在 2026-11-22 会话中提供的总控 Prompt（阶段 01、阶段 02 两轮）整理落库。**本文件不是逐字复制**；如与用户后续明确指令冲突，以用户新指令为准。
目的：让后续阶段在换模型、换工作区或新会话时，仍能从仓库读取同一份最高优先级规则，避免规则丢失和越阶段。

## 1. 产品目标

- 交付一个 PC 优先的石油产业链沉浸式科普体验，包含：连续三维世界、五关任务、知识内容、AI 问答/创作入口。
- 产品气质：真实工业、暖砂岩/旧钢/黄铜、地下到城市的昼夜推进；不做深色霓虹科技展台。
- 本期明确不承诺手机端；桌面 1366×768–1920×1080 为主。
- 所有设备/工艺是教学示意，不是工程仿真、数字孪生或真实生产数据。

## 2. 阶段与门禁

| 阶段 | 名称 | 核心交付 | 允许改代码？ |
|---|---|---|---|
| 01 | 审计基线 | 仓库/页面/资产/交互/测试基线 | 否 |
| 02 | 体验设计 | 方向、用户、地图、任务、镜头、交互、视觉、知识映射、Hero 规格、签收页 | 否（只文档） |
| 03 | 世界骨架 | 六区/对象注册表/会话/相机骨架；可标注占位资产 | 是 |
| 04 | 地下体验 | 地下 Hero、井筒/井口、HM-1 | 是 |
| 05 | 处理与储运 | 分离器内部/三相路径、储罐、HM-2 | 是 |
| 06 | 炼化与塔 | 塔半剖/全剖、馏分、城市交付、HM-3 | 是 |
| 07 | 系统整合 | 三模式、AI、音频、任务持久化 | 是 |
| 08 | AI 与创作闭环 | 设备级上下文、生成回写；不破坏 `/api/ask` | 是 |
| 09 | 回归验收 | 真实浏览器、性能、用户测试、资产/授权核对 | 是（修复） |

规则：

1. 一次只推进一个阶段；未获用户签收不得进入下一阶段。
2. 每阶段开始前重读本文件、阶段 Prompt、上一阶段 handoff 和前置交付物。
3. 阶段 02 只做设计，不得提前写阶段 03 代码。
4. 阶段 03 不得重命名现有稳定 ID/字段；新增 ID 必须登记。
5. 不得用历史文档/记忆替代当前代码与实测。

## 3. 状态

- `PASS`：任务与证据齐全，Agent 可建议 PASS；仍须用户签收。
- `REVISE`：有问题需修订；不得进入下一阶段。
- `BLOCKED`：外部条件/用户门禁阻塞；不得用“部分完成”冒充通过。
- `NOT_STARTED`：前置文件缺失或未开始；停止并说明缺失项。
- 任一 P0 未关闭 → 不得建议 PASS。
- Agent 只能建议，不能代替用户签收；签收语句必须由用户本人发出。

## 4. 证据规则

- 未执行的测试写“未执行”，不得写“通过”。
- HTTP 200/语法通过不能代替视觉/交互/性能通过。
- 截图/录屏必须来自真实浏览器，不用设计稿/Blender 静帧冒充网页。
- 设计阶段可交付参考图/灰盒，但必须标注“非最终资产/非网页截图”。
- 不编造压力、温度、流量、产能、收率、排放量、用户数据。
- 第三方资产/字体/贴图必须记录来源和许可证；未授权不得标“可商用”。

## 5. 资产门禁

- 阶段 02：完成 Hero Asset 设计规格、参考板、格式、语义节点、来源策略、阶段责任、验收标准。
- 阶段 03：允许使用**明确标注的占位资产**搭建世界骨架；占位不得通过视觉终验。
- 阶段 04：地下地质/井筒 Hero 未达 → 地下体验视觉验收 BLOCKED。
- 阶段 05：分离器内部剖切/语义节点未达 → 处理体验不得 PASS。
- 阶段 06：塔全剖无结构级差异 → 炼化体验不得 PASS。
- 阶段 09：三类 Hero 的 `.blend`、来源/许可、网页证据缺一不可。
- 除非用户明确要求提前，不得把阶段 04–06 的资产交付责任提前为阶段 02/03 的启动门槛。

## 6. 体验与设计原则

- 用户主动探索优先于自动播放；操作必须产生可观察的三维反馈。
- 三个 Hero Moments：打开地下世界、亲自完成三相分离、让蒸馏塔打开。
- 批次 YJ-001 是教学追踪标记，不是原油/设备零件/管线内实体。
- 蒸馏塔：馏分≠成品油；常压/减压关系明确；不编造收率。
- 分离器：按相态/密度分离，不是过滤；火炬是安全泄放，不估算排放。
- 储罐：浮顶减少油气空间，但不是零损耗；固定顶不是不能用。
- 塑料不一定来自石油；产品路线是典型示意，非唯一。
- 颜色/线型只是教学编码；不得称为真实 CFD/流场/工程仿真。

## 7. 阶段 02 签收门禁

阶段 02 必须在以下全部满足后才能签收：

1. 三方向比较与主方向明确；
2. 用户身份/目标/叙事/三个 Hero Moments；
3. 三层地图与空间构图；
4. 主线 + 自主探索任务与完整因果链；
5. T0–T7、五关、六步骤、五知识章口径一致；
6. 五种馏分与终端应用映射、科学边界；
7. 镜头字段 + 三个 Hero 各六帧分镜；
8. 六维正交状态、设备能力矩阵、actionId、上下文兼容；
9. 视觉参考/UI 层级/Token/性能预算；
10. Hero 规格/格式/阶段责任/验收；
11. 用户测试方案（N=5）与验证标准；
12. 设计—研发追踪表；
13. 用户本人签收“体验设计通过，放行进入阶段 03”。

未满足时保持 REVISE，不得开始阶段 03。

## 8. 交接要求

每阶段 handoff 必须包含：状态、任务逐项、修改文件、起止 Commit（真实 SHA）、执行命令、证据、P0/P1/P2、资产状态、用户签收、停止声明。
不得只写“见 git log”；必须记录可复核的最终提交/分支/工作区状态。
